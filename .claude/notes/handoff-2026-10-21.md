## Verified facts (Paseo 0.12.0, from the Mac)

- Windows assets: `Paseo-Setup-<v>-{x64,arm64}.exe` (NSIS) and
  `Paseo-Setup-<v>-{x64,arm64}.zip`. The zip is the unpacked app: `Paseo.exe`,
  `resources/app.asar`, `resources/app-dist/`, `resources/app-update.yml`
  (provider github, to be neutered like on mac), `resources/bin/paseo.cmd`
  (the daemon CLI; the swap needs `paseo.cmd daemon stop`).
- `latest.yml`/`beta.yml` list only the `.exe`s, not the zip. The GitHub API
  `assets[].digest` gives `sha256:…` for every asset.
- Unsigned: the PE security directory is empty for both the Setup `.exe` and `Paseo.exe`.
- Electron 44.2.0. Fuses on Windows `Paseo.exe`:
  `EnableEmbeddedAsarIntegrityValidation` off and `OnlyLoadAppFromAsar` off, so
  the edited asar loads without updating the embedded `ElectronAsar` resource.
  Re-check this each release: if Paseo turns the fuse on, the build has to rewrite that resource.
- All 52 patches (`patchAsar`, `patchRenderer`, `patchIndexHtml`) apply on Windows
  with 0 MISSED. The Windows `index.html` uses CRLF and is still matched. The renderer
  bundle hash differs from the mac one.
- Windows window options: `frame: false, autoHideMenuBar: true`
  (`getMainWindowChromeOptions`, mode other than `native-mac`), with the same
  `createWindow` and asar anchor as on mac.

## Electron on Windows

- No `setVibrancy`. Use `setBackgroundMaterial('auto'|'none'|'mica'|'acrylic'|'tabbed')`,
  Windows 11 22H2 or later only. The blur radius is fixed, so `blur.node` and CGS do not apply on Windows.
- electron#49443: acrylic works only with `transparent: true`.
- electron#47510: with transparent and acrylic together, the window loses Win11's rounded corners.
  Closed as not planned.
- From the docs: transparent windows can't be maximized by double-clicking the title bar or from
  the system menu, and are "not resizable". Whether edge resizing actually breaks is **unverified**.

## Port surface (the plan before the port; see section 6 and the knowledge file for what was built)

| File | Mac-specific | Windows plan |
| --- | --- | --- |
| `release.ts` | arm64 zip from `*-mac.yml`, `ditto`, `codesign -R` | `Paseo-Setup-<v>-{x64,arm64}.zip` (by `process.arch`), GitHub digest, `tar.exe -xf`, no identity check |
| `build.ts` | `ditto`, `Contents/`, PlistBuddy, codesign, `Info.plist` version, blur compile | `fs.cp` into `resources/`. Skip plist, signing and compile. Version from the release tag or the asar's `package.json` |
| `swap.ts` | `sh`, osascript, `pgrep`, `~/.Trash`, `open -a` | Detached PowerShell: `paseo.cmd daemon stop`, wait for processes started from the old dir to exit (Windows locks a running `.exe`), move/rename dirs, `Start-Process`. Keep stripping `ELECTRON_*` from the environment |
| `status.ts` | walks the path to a `.app` | the folder containing `Paseo.exe` |
| `settings-file.ts` | `~/Library/Application Support/Paseo` | `%APPDATA%\Paseo` (= `app.getPath("userData")`) |
| `index.server.ts` | `~/Applications/Paseo-Vibrancy.app` | `%LOCALAPPDATA%\Programs\Paseo-Vibrancy` + Start Menu `.lnk` |
| `main-hook.ts` | `setVibrancy`, `blur.node`, matchCorners | `setBackgroundMaterial` when `process.platform === "win32"` |
| `shared/vibrancy.ts`, `VibrancyScreen.tsx` | Apple materials, blur radius | material list per platform, hide blur radius |
| `ghostty.ts` | `~/.config/ghostty/config` | harmless (no Windows Ghostty build). Possibly hide the toggle |
